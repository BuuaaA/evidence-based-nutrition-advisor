# 证据生成前的点击式关键信息收集

本流程只用于普通用户的个人决策问题。目的不是建立完整病史，而是在检索前确认那些会改变 PICOS、安全边界或购买建议的信息，让用户尽量通过点击完成，不必先学会写精确提示词。

## 1. 什么时候先问

先区分两类问题：

- **一般证据问题**：用户明确只想知道某种干预通常有没有用。直接按常见情境检索和回答，不读取健康档案，不弹出问卷。
- **个人决策或意图不明**：对每个缺失变量执行 `rapid-audit.md` 的“决策翻转测试”。只要答案可能改变证据人群、干预形式、关键结局、安全红线、医学评估需求或最终使用判定，就在完整检索和答案生成前收集。

若正在出现急性或危险信号，先给最短的安全处置提示，不等待问卷完成。

## 2. 问什么

- 通常选择 **3–5 项**，硬上限为 **5 项**；若真正会改变决策的变量只有 1–2 项，就只问 1–2 项，不为凑数增加低价值问题。
- 优先问能直接映射到 PICOS 和安全判断的变量：目标结局、诊断或症状部位、关键化验档位、计划使用的剂型/剂量、相关用药、明确的高风险状态。
- 不默认询问年龄、性别、完整疾病史或完整用药表。只有某个具体人口学或生理状态本身会改变建议时才问，例如孕哺、绝经状态或儿童年龄段。
- 不重复询问当前对话中已明确的信息，也不重复询问已启用档案中有日期且仍可用的信息。
- 每题提供 2–7 个用户能识别的选项；单选项互斥，多选项可组合。应提供“不清楚/没有结果”选项。每题用一句话说明“为什么问”或答案会改变什么。
- 允许单选或多选；多选中的“均没有”和“不清楚”必须与其他项互斥。非安全必答题可以跳过。
- 不要求用户输入姓名、联系方式、完整病历、证件号或账号凭据。
- A/B/C、1A/2B 等代码只能作为内部值，绝不显示为用户作答方式。

## 3. 交互能力路由

以下是不可跳级的状态机，不是三个可任选方案：

1. 先检查宿主原生选择控件；可用则走路径 A。
2. 原生控件不可用时，单独检查本地问卷：只要能够运行本地脚本、绑定 `127.0.0.1`、向用户交付可点击链接并读取回答，就走路径 B。自动替用户打开浏览器不是必要条件。
3. 只有路径 A 与路径 B 已分别确认不可用，才走路径 C。进入路径 C 前，Agent 必须能够指出本地问卷失败的具体原因，例如本地进程不能启动、端口不能绑定、链接无法交付或回答无法回读；“当前是 Default 模式”“原生工具仅限 Plan 模式”“不想启动本地服务”或“不能自动打开浏览器”都不是路径 B 失败的充分理由。

原生控件不可用不等于本地问卷不可用。不得从路径 A 直接跳到路径 C，也不得把宿主协作模式误当成本地脚本能力。

### 路径 A：宿主原生选择控件

宿主能够显示单选、多选、表单或选择卡时，优先一次展示全部问题。提交按钮使用“按这些信息生成证据”，并提供“跳过，先看一般结论”。收到选择后再确定最终 PICOS、运行检索并生成证据。

### 路径 B：一次性本地问卷

宿主没有可回传答案的原生控件，但允许运行本地脚本并提供可点击的 localhost 链接时，使用 `scripts/collect_intake.py`。若不能自动打开浏览器，直接把脚本输出的链接交付给用户；这不构成降级到路径 C 的理由。不要制作只有外观、无法把选择返回给 Agent 的静态弹窗。

**自动续跑契约**：本地页面不能唤醒一个已经结束的 Agent turn。启动脚本后，Agent 必须保留同一轮任务处于运行状态，并等待该脚本进程退出；不得在只交付问卷链接后发送 final、要求用户再打字“已提交”或开始新一轮。提交会写入回答并使进程退出，正在等待该进程的 Agent 随即自动继续。

1. 在系统临时目录创建问卷 JSON 和回答 JSON 路径；不得写入 Skill 目录、Git 仓库或公开产物。结构参见 `templates/intake-questionnaire.sample.json`。
2. 以可继续读取的长运行会话启动一次性服务：

```powershell
python scripts/collect_intake.py questionnaire.json --response response.json
```

3. 读取脚本输出的 `url` 并在本机浏览器打开。该页面只绑定 `127.0.0.1`，使用随机路径令牌，不加载外部资源。自动打开失败时直接提供可点击链接，不得因此改为要求用户手工回报。
4. 页面以卡片显示单选/多选，提交前显示自然语言摘要；用户可以返回修改。最终提交后才写入结构化回答 JSON，并自动关闭一次性服务。
5. Agent 留在同一轮中等待该会话：每次等待不超过 60 秒，可在等待间隙做缓存查询或准备候选来源，但不结束本轮。脚本输出 `status=ok` 后立即读取回答 JSON，不要求用户复制、粘贴或发送任何确认消息。
6. 回答中的 `submitted_at_utc` 是快速路径计时起点，`quick_result_deadline_utc` 是3分钟首个结果的硬截止点。若 `skipped=true`，按一般情境继续；否则把 `answer_labels` 映射进 PICOS、适用性和安全判断。
7. 使用完成后删除临时问卷和回答文件。不要把个人健康选择提交到仓库、证据缓存或公开产物。

只有长运行会话在当前宿主确实无法继续读取或等待时，才允许把链接作为 final 交付；此时成功页和聊天都必须诚实说明需要用户回来继续，不能声称已自动续跑。

本地问卷只是交互桥梁，不负责医学判断，也不能替代 Agent 对选项设计、PICOS 和证据的审计。

### 路径 C：自然语言逐题降级

前两种路径已经分别检查且都不可用时，一次只问一个自然语言问题，并直接列出语义完整的选项，例如“未检测 / 偏低 / 正常 / 不清楚”。不得要求用户回复字母、数字或组合代码。收到自然语言答案后再问下一项；用户可以随时说“跳过，先看一般结论”。如果路径 B 只是无法自动打开浏览器，但仍能提供可点击链接，则路径 B 仍然可用，不得进入本路径。

## 4. 收到选择后

1. 用答案确定检索所需的 PICOS 和产品边界；不得只把答案当作最后的文案装饰。
2. 用户主动提供产品标签时，把每份用量、成分毫克数、品牌或商标原料、标准化比例、植物部位和使用频率拆成独立事实后再做产品匹配；不得因为记录了“提取物 280 mg”就遗漏同一句中的“Shoden®”或“35% 标准化”。用户后续补充的信息应立即并入当前判断，除非与已有信息真正冲突。
3. 输出前逐项核对 `remaining_uncertainties`：凡当前对话已经直接回答的项目必须删除或收窄，不能继续写成“尚未核实”。若标签措辞确有歧义，只指出具体歧义，例如“35%指总醉茄内酯还是醉茄内酯糖苷”，不得退回笼统的“剂量和标准化未知”。
4. 若答案显示需要医学评估、存在相互作用或不适合自行使用，安全判断先于购买建议。
5. 先按 `fast-path.md` 生成 L1-Quick 或复用已审计缓存；只有进入 L1-Audited 时，才运行 `rapid-audit.md` 的 PubMed 全量导出、筛查与逐结局确定性流程。
6. 在结果的“适不适合我”中列出本次已采用的信息、与研究人群的匹配度及仍未解决的不确定性。首次关键问题不应再藏在展开层中。
7. 用户选择“不清楚”或跳过时，仍生成一般证据，但必须写明暂定情境、匹配度未知和不能据此得出的个体化结论。

## 5. 停止条件

完成一次关键信息收集后，不因证据检索过程中出现新的低价值背景变量而再次弹出问卷。只有发现会立即改变安全处置或使现有 PICOS 无效的新问题时，才补问一项，并说明原因。
