# 问题界定与安全分流（M1）

本流程在证据检索前运行，目标是尽快界定用户要作出的判断、识别需要先处理的安全问题，并只收集会改变证据范围或行动建议的信息。它不是病史采集，也不代替临床诊断。

## 1. 先分流，再追问

先判断用户在问什么：

- **一般证据问题**：用户只问某干预通常是否有效、安全性如何或证据如何；按常见目标人群界定问题，不索取个人健康信息。
- **个人决策问题**：用户问自己/家人能否使用、是否值得购买或怎样使用；只追问可能改变适用性、剂量/产品匹配、安全处置或行动建议的信息。
- **产品或宣称核查**：用户想评估某产品、配方或营销说法；保留用户已给的品牌、完整配方和标签事实，不把一般成分证据冒充该成品的直接证据。
- **研究任务**：用户已明确要求检索、审计或合成时，直接记录其范围和授权；不重复问是否要做同一项工作。只补问会改变方案且尚未知的条件。

若用户描述了可能需要紧急处置的症状或危险情境，先简明给出寻求当地急救/及时医疗评估的安全下一步；不等待问卷、搜索或证据卡。不要诊断，也不要用营养干预延误必要处置。非紧急但涉及禁忌、相互作用或需要诊断的信息，先说明边界，再决定是否还可给一般证据。

## 2. 最少必要追问

### 2.1 决策翻转测试

对每个候选问题，先写下至少两个可能答案及其对处理的影响。只有答案会改变以下一项时才询问：

1. 研究目标人群或用户与研究人群的匹配；
2. 干预、剂型、剂量、配方或对照的选择；
3. 重要获益、安全风险或需要就医评估的结局；
4. 建议行动（如可考虑、先核实、避免自行使用）；
5. 用户明确要求的研究范围或方法。

不能说明答案如何改变判断的问题不问。能从对话、用户给的标签/文件，或用户已启用且仍有效的资料中可靠取得的信息不重复问；记录已知信息的来源与日期。缺失但不影响本轮一般结论的信息不追问。

### 2.2 数量与呈现

- 默认一次询问 **1–3 个**最关键的问题；必要时最多 **5 个**。问题更少即可界定时，不为凑数增加问题。
- 优先以一组清晰的单选/多选问题一次收集，避免逐轮盘问。每题用一句话说明为什么会影响判断。
- 选项应互斥且容易理解；提供“不清楚/没有结果”。非安全关键项允许跳过。安全信息未知时，不给依赖该信息的个体化使用建议，可转为有边界的一般回答。
- 普通用户不需要自行撰写 PICOS，也不要求使用 A/B/C 或数字代码作答。
- 不默认询问年龄、性别、完整病史或完整用药表。仅当具体年龄段、生理状态、疾病、用药或检查结果会改变判断时，询问对应的最小信息。
- 不收集姓名、联系方式、证件、账号凭据或与本次判断无关的健康信息。

### 2.3 常见问题类型对应的信息

下列为候选项，不是固定问卷。只问与当前问题相关且未知的项目。

| 问题类型 | 可能改变判断的最小信息 | 不应机械推问 |
|---|---|---|
| 营养素/补剂是否有用 | 目标结局；若是个人建议，是否有明确缺乏或相关检查；准备使用的产品/剂量（当剂量影响匹配时） | 全面病史、与目标无关的生活习惯 |
| 症状或疼痛 | 具体症状/部位、已知诊断；出现会改变安全处置的危险信号 | 把所有症状问题都当成已确诊疾病 |
| 长期饮食或暴露 | 暴露/饮食定义、比较情境、关注的健康结局与大致时间范围 | 把短期试验人群直接视为长期结局人群 |
| 产品购买/配方 | 标签中每份剂量、完整成分、品牌原料/标准化信息、用户关心的结果 | 只问品牌而不核实具体配方；假定成分证据等于成品证据 |
| 安全/相互作用 | 涉及的具体产品与剂量、相关药物或风险状态 | 在没有关联理由时索取完整用药清单 |
| 用户要求的研究 | 数据库、纳排范围、主要结局或分析选择中尚未知且会改变方案的项目 | 再问用户是否想做其已明确要求的审计/合成 |

## 3. 形成内部 PICOS / 问题规格

追问结束后，先把用户自然语言整理成内部 `QuestionSpec`，再检索。普通用户只需看到简短的目标确认，不需要看到方法学术语表。

至少记录：

| 字段 | 记录规则 |
|---|---|
| `question_type` | 一般证据、个人决策、产品/宣称、安全或研究任务；可多标签 |
| `population` | 目标人群、适用条件及用户信息；区分已知、未知、暂定 |
| `intervention_exposure` | 营养干预、剂型、剂量、配方或饮食/暴露定义 |
| `comparator` | 对照、替代方案或常规照护；未说明时标记待研究定义 |
| `outcomes` | 用户目标及重要获益/风险结局；不能把“血脂”等宽泛词自动当成单一结局 |
| `time` | 与问题相关的观察/干预时长；不能把短期指标变化等同长期临床结局 |
| `study_designs` | 按问题选择合适设计；疗效、安全、长期暴露、预后问题的设计需求可能不同 |
| `context_and_constraints` | 地区/产品、用户给定限制、请求的数据库或输出范围 |
| `safety_flags` | 可能影响是否自行使用或是否先就医的信号及处理状态 |
| `known_unknowns` | 每项注明未知原因及其是否限制个体化判断 |
| `revision` | 信息更新后递增；旧版本结果不得覆盖新版本结论 |

PICOS 是检索和纳排的工作框架，不强迫所有问题都套入干预试验模板。对长期饮食暴露、风险/病因或预后问题，应明确相应人群、暴露、比较、结局、时间与可接受研究设计。研究设计由问题决定；不能仅凭“队列研究”或“随机试验”标签预先判定证据质量。

在信息不足时，标明采用的暂定情境及其后果。若未知项会翻转安全处置，暂停个体化行动建议；若只影响精确匹配，仍可给范围明确的一般证据，并说明不能外推到用户个人的部分。

## 4. 产品事实与资料复用

用户给出产品标签、文件或先前回答时，逐条提取并保留：每份用量、成分剂量、品牌原料、植物部位、标准化比例、剂型、使用频率及资料出处。复述时不得丢掉剂量单位或品牌原料。若标签表达确有歧义，只指出具体歧义并询问会改变判断的那一项；不得笼统把已提供信息重新标为“未知”。

当前对话中已确认且未被更正的信息可直接复用。已启用的个人资料只有在用户授权的范围内、带有时间信息且仍适用时才可复用；否则询问是否需要更新。不得把个人健康事实写入通用证据包或共享研究缓存。研究缓存是否匹配由 M2 判断，M1 只提供已界定的问题和用户适用性事实。

## 5. 交互能力与状态

按当前宿主真正可用的能力选择交互形式：优先宿主原生单选/多选；否则可用本地问卷；两者都无法回传时才用自然语言追问。不要声称静态页面可启动后台任务，也不要把按钮点击当作用户已同意深入研究。

无论使用哪种交互：

- 问卷提交前允许修改；重复提交不得重复启动同一任务。
- 用户跳过或选择“不清楚”时，继续回答其一般证据问题；标明暂定人群、匹配度未知及个体化结论边界。
- 用户修改会改变建议的答案时，创建新 `revision`，重新核对适用性；旧版本结果不能覆盖新版本。
- 检索期间只有发现会立即改变安全处置或使问题范围失效的新信息，才补问必要的一项，并解释原因；不能因为发现低价值背景信息再次弹整套问卷。
- 用户已明确要求长任务时按现有授权执行；否则 M1 仅交付问题规格，不自行推断用户同意耗时审计或 Meta。

## 6. 交付给后续模块

M1 向 M2–M5 传递 `QuestionSpec`，至少包含：问题类型、PICOS/适配的问题框架、已知与暂定信息、关键结局、安全标记、剩余不确定性、授权范围及修订号。下游不得再次索取已明确的信息；若新发现的事实确实会改变判断，先更新规格和版本。

最终答复在用户需要个人建议时，应简要说明本轮采用了哪些个人信息、与目标证据人群的匹配程度和仍未解决的不确定性。用户跳过问题时，回答一般情境，不伪装成个体化结论。

## 7. 停止条件

以下条件满足后结束 M1 并进入后续工作：

1. 已识别问题类型及用户要作出的判断；
2. 任何需要优先处理的安全信号已先行回应；
3. 已收集会改变问题范围/建议的最少信息，或记录用户跳过/未知；
4. 内部问题规格、重要结局、允许的研究设计和授权范围已足以指导下一模块。

不要为了填满字段继续追问。发生信息更新时只重开受影响的字段；只有新事实使现有范围失效或改变安全处置时，才重新确认问题规格。
