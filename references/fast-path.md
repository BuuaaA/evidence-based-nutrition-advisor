# 普通用户快速交付路径

目标：在不越过科学边界的前提下，尽快交付可行动、可追溯、可升级的 HTML 证据卡。安全分流、L1-Quick 和 L1-Audited 是逐级增强，不是把完整审计压缩成 90 秒。

## 路由顺序

1. **15 秒内安全分流**：当前输入触发红旗或医学处置阈值时立即提示，不等待问卷、缓存、HTML 或检索。
2. **先离线查包**：主题可识别后立即运行 `python scripts/evidence_cache.py lookup --topic TOPIC_ID`。个人决策需要问卷时，不等待用户提交才开始查包；问卷填写时间可用于完成缓存状态和候选来源准备。
3. **只收集会翻转决策的信息**：个人决策按 `pre-evidence-intake.md` 收集 0–5 项。不得向普通用户展示 A/B/C、1A/2B 等内部代码。本地问卷启动后保持同一轮等待，提交后自动续跑，不要求用户另发消息。
4. **已审计缓存命中**：`fresh` 且范围直接匹配时，从包内决策矩阵生成 `L1-Audited（缓存命中）` HTML 卡，不先联网。
5. **缓存未命中或不匹配**：先按 `evidence-assurance-levels.md` 完成 L1-Quick。只核验三类高权重来源，不同步等待全量 PubMed 审计。
6. **默认生成并打开 HTML**：关键信息收集完成后，普通用户无需再次要求。聊天只给最短判定、异常说明和文件入口。
7. **按风险与用户意图决定升级**：用户明确要求完整/专业审计，或风险足以需要更高保证时，继续 L1-Audited；否则写明暂停或仅按需升级。继续审计也不得阻塞快速卡。

L1-Quick 不逐篇等待全文，也不运行从头全历史 PubMed 检索。若升级为普通 L1-Audited 且没有可信历史基座，默认完整检索并筛查最近 10 年；有基座时只更新其检索截止日后的记录。L2-Research 或用户明确要求全库、全时间、不限年份时才检索全部年份。这个限制应减少宽泛问题的命中量，但 90 秒快速卡仍不得等待后续全文审计。

## 硬时间预算

- 15 秒：出现安全分流或清晰进度；
- 60 秒：出现初步可行动判定；
- 90 秒：HTML 快速证据卡可打开；
- 180 秒：普通用户首个可打开结果的绝对截止点；达到时停止扩展，按当前证据状态交付，不静默延长到完整审计。

有问卷时，从回答文件的 `submitted_at_utc` 开始计时；没有问卷时，从收到足以确定问题的用户输入开始计时。`quick_result_deadline_utc` 由问卷脚本写入回答文件，生成器用它报告是否满足3分钟 SLA。

### 三分钟执行盒

- **0–20 秒**：读取问卷、完成安全分流、锁定 PICOS 和产品边界，同时复用已经开始的缓存查询。
- **20–90 秒**：缓存未命中时，只核验三类必需来源。优先一次批量查询；每个来源角色最多打开 1 个决定性页面。没有用户要求时，不在首卡前逐篇追踪参考文献。
- **最多补 1 项直接人体证据**：仅当它会改变效果方向、效果上限或安全处置时补充；更多原始研究、全文和争议追踪留到 L1-Audited。
- **90–150 秒**：锁定结构化判断，生成并校验 HTML；不要先写长篇聊天摘要。
- **150–180 秒**：只处理生成错误或降级交付。若三类来源仍未齐，输出 `快速核验中`、`仅安全分流` 或 `证据覆盖受限`，并列出缺口；不得继续扩搜。

时间目标不允许伪造来源或越级声称。三类最低来源在截止前仍无法核验时，不得生成确定性购买结论。首个 HTML 交付后可以按用户要求继续深入，但后续工作不得延迟首卡。

## 缓存状态

- `fresh`：经范围门控后，直接生成已审计缓存卡；不在首答前增量检索。
- `stale`：先用当前权威来源生成 L1-Quick；旧包只能作为明确标注过期的历史背景。完整审计从 `last_search_end` 次日增量更新。
- `missing`：先生成 L1-Quick；完整审计是否继续由风险和用户意图决定。
- `invalid`：视为不存在，不能绕过校验。

增量审计完成后，重新运行 `validate` 才能移动证据包日期。运行时证据包写入本地索引并保持在版本控制之外；不开源分发预填充种子证据包。

## 同一卡片升级

快速卡与审计卡使用同一输出路径。生成器通过 `card_state` 显示状态；更新时覆盖该卡的结构化输入和 HTML。若结论发生实质变化，使用 `recommendation_updated`，并填写 `previous_verdict` 与 `change_reason`，禁止静默覆盖。

当前宿主无法在最终答复后继续工作时，不承诺后台运行；将状态写成“完整审计按需进行”或在当前任务内先交付快速卡，再继续可见地更新同一文件。

## 体验验收

- 问卷页面只显示自然语言标签，自动写回临时 JSON；
- 问卷提交后无需用户再发送“已提交”，同一轮任务自动继续；
- 缓存命中路径首答前不调用网络；
- 缓存未命中路径不会等待全量 PubMed 筛查才首次交付；
- 快速卡明确写“不是系统综述或正式 GRADE”；
- 生成器报告从问卷提交到 HTML 的耗时及是否满足180秒 SLA；
- HTML 是普通用户默认产品界面，安全红线不因视觉生成而延迟。
