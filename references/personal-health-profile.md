# 可选个人健康档案与效果追踪

本模块只在用户明确希望记住健康信息、减少重复询问或长期追踪营养干预时启用。提供健康信息不等于授权持久化；拒绝建档不影响证据评估。

## 1. 何时不读取或不建档

- 一般知识、机制或非个性化证据问题；
- 用户只是粘贴产品、博主观点或论文要求审计；
- 明确代问朋友、家人、患者或其他人，且没有要求建立独立档案；
- 当前任务不需要健康信息即可回答；
- 用户拒绝、撤回同意或要求临时会话处理。

不要为了“以后可能有用”收集信息。

## 2. 功能发现与邀请时机

用户不需要了解 Skill 触发规则。若档案提示状态为 `unknown`，且同时满足以下条件，应主动展示一次非阻断式邀请：

- 用户询问的是自己的个性化营养问题；
- 对话已经出现疾病、用药、化验、饮食限制、营养干预或效果追踪信息；
- 保存少量信息能明显减少以后重复询问或改善连续判断；
- 不是代问他人、纯知识问题、一次性文献审计或需要先处理的紧急安全场景。

邀请必须放在本轮核心回答之后，不能作为获得结论的前置门槛。使用 `templates/profile-invitation.md`；平台支持交互卡片或按钮时可以显示按钮，不支持时使用同等内容的普通对话。Skill 本身不能假定宿主平台一定支持真正的弹窗。

建议维护非健康性质的提示偏好：

```yaml
health_profile_prompt:
  status: unknown | enabled | snoozed | declined
  last_prompted: YYYY-MM-DD
```

| 状态 | 行为 |
|---|---|
| `unknown` | 下一次符合上述情境时邀请一次 |
| `enabled` | 按本文件的档案规则运行，不再邀请 |
| `snoozed` | 默认 90 天内不主动重复；用户主动询问时可随时启用 |
| `declined` | 不再主动提示；只有用户重新提出“记住、建档、长期追踪”时恢复 |

如果宿主环境无法持久保存提示偏好，只能保证当前会话不重复提示，并诚实说明不能跨会话记住拒绝状态。

## 3. 启用流程

第一次确实有长期价值时，用一句话说明用途并询问：

> 为了以后少重复询问，并追踪补充后的效果，你是否希望建立一份可查看、可修改、可删除的个人营养健康档案？不保存也不影响这次分析。

用户同意后再确认存储方式：

1. 平台提供且用户同意的安全记忆；或
2. 用户指定的、本地且位于 Skill/Git/共享目录之外的 Markdown 文件。

不得硬编码开发者自己的路径。若没有合适的持久化位置，使用当前会话临时信息，并说明尚未落盘。

默认更新策略为“每次写入前确认”。用户可主动选择“自动写入并在回复中列出本次变更”，但敏感或重大变化仍应明确提示。

## 4. 最小信息原则

只保存会改变营养证据适用性、安全性或效果追踪的信息：

- 年龄段及与问题相关的生理状态；
- 孕期、备孕或哺乳状态；
- 相关疾病、手术计划、过敏和不耐受；
- 与当前营养问题有关的药物和补充剂；
- 有日期、单位和参考范围的相关化验值；
- 主要饮食限制、可能的缺乏风险和现实生活约束；
- 用户定义的目标和重要性；
- 补充试用的成分、产品/剂型、剂量、起止日期、效果指标和不良反应。

默认不保存姓名、证件号、联系方式、精确地址、机构账号、完整病历或与营养决策无关的信息。优先使用年龄段而非出生日期，使用用户自选档案代号而非真实姓名。

## 5. 本人、代问与多档案隔离

出现“朋友、家人、孩子、患者、同事”等信号时，不读取本人档案来推断对方情况。

- 默认将他人信息视为本次会话临时资料；
- 若用户要求长期追踪他人，先确认是否建立独立档案以及用户是否有权保存该信息；
- 每份档案必须有不含真实身份的唯一代号和 `profile_subject`；
- 不把不同人的化验、药物、补充剂或效果记录合并。

## 6. 读取与新鲜度

- 只加载本次问题相关部分，避免把完整敏感档案送入不必要的上下文。
- 当前对话信息优先于旧档案；出现冲突时按当前信息分析，并询问是否更新。
- 每条化验值和干预记录必须带日期；没有日期时标为“日期未知”。
- 用药、孕哺、手术和近期严重疾病在相关决策中应再次确认，不能仅依赖旧记录。
- 档案整体超过 6 个月未核对时，只问一句是否有重要变化，不要求重新填写完整问卷。

## 7. 首次建档的轻量顺序

不要一次发长问卷。围绕当前问题分批收集：

1. 会改变安全性的内容：相关疾病、处方药、孕哺、过敏、手术；
2. 会改变适用性的内容：目标、基线饮食/缺乏状态、关键化验；
3. 仅在用户愿意长期追踪时记录生活约束、既往补充经历和个人偏好。

一般证据问题可以直接给结论。当前问题属于个人决策且缺失信息会改变建议时，首次关键信息按 `pre-evidence-intake.md` 在证据生成前一次收集；这不等于建立或补全长期健康档案。

## 8. 写回与审计轨迹

使用 `templates/health-profile.md`。每次更新：

- 修改当前状态字段时保留 `last_verified`；
- 化验、用药和补充剂使用按时间线追加，纠错时注明更正而非静默改写历史；
- 记录本次证据结论只保留短摘要与日期，不复制整篇回答；
- 写入后向用户列出新增或修改的字段；
- 不确定信息标为“用户未确认”，不得推测填充。

用户可随时要求查看、导出、更正、停止更新或删除档案。删除前确认准确目标；完成后说明删除范围和是否存在用户自行保留的副本。

## 9. 效果追踪

个人体验用于个体决策，不提升群体证据等级。开始试用前尽量记录：目标指标、基线、预计观察时间、同时发生的生活方式/药物变化和停止条件。

回访时记录：

- 是否按计划使用及实际剂量；
- 目标指标变化和测量方式；
- 不良反应；
- 同期睡眠、饮食、运动、疾病或药物变化；
- 继续、停止或寻求专业评估的决定。

解释时考虑安慰剂效应、回归均值、自然波动和同期改变。单人的前后变化不能证明因果，也不能替代安全性评价。
