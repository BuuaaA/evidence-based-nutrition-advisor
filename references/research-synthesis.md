# 单数据库 Meta 证据合成

用于用户明确选择开展单数据库 Meta 证据合成，且这个定量合成有望回答预先界定的决策问题时。缺少综述、综述质量低、发现新研究或既有结论评级低，都只是评估是否升级的信号，不会自动启动 Meta。先判断证据范围是否清楚、研究是否可能可比、关键数据是否可得、合并结果是否会改变理解或行动；不满足时交付结构化叙述综合并说明原因。

这不是发表级系统综述。单数据库可能遗漏其他数据库和未发表研究；全文不可得也会造成选择性证据缺失。标题、方法和结论必须同时写明数据库名称、检索截止日期、筛选方式和全文可得性，不能使用“全面检索”“完整系统综述”或“发表级 Meta”等表述。

## 术语约定：PICO 与 PICOS

本 Skill 用 **PICOS** 作为完整纳排框架的简写。其方法学含义与 [Cochrane Handbook 第 3 章](https://training.cochrane.org/handbook/current/chapter-03) 一致：综述问题用 PICO 表达，预设纳排标准还必须明确允许的研究类型。换言之，PICO 可以描述临床问题，但不能替代 `S`（Study design）；数据库检索是否加入研究设计过滤器，则应按召回率、索引状态和已验证过滤器单独决定。

## 0. Meta 类型确认

用户提出“Meta 分析”“能不能重新合并”，但未明确是评价既有综述还是重新提取原始研究时，必须先问：

> 您是希望核查已有 Meta 分析，还是基于一个预先指定的数据库和可获得全文，重新完成一次 Meta 证据合成？

在用户选择之前不先展示现有 Meta 结论，避免把“找到并总结一篇 Meta”和“重新提取原始研究并合并”混为一谈。

- 选择“现有 Meta 的证据审计” → 返回专业证据审计，评价检索覆盖、纳入研究、重复数据、RoB、统计模型、异质性、发表偏倚、结论方法、更新程度和利益冲突；不执行新的定量合并。
- 选择“单数据库 Meta 证据合成” → 继续本文件流程。

如果用户已经明确说“审计这篇/这些既有 Meta”或“基于某数据库和可获得全文重新合并”，选择已经完成，不重复询问。

## 1. 启动前确认

确认以下事项；用户已经说明的不要重复问：

- 需要回答的证据空白，以及为什么现有结论不可靠或不够新；
- 用途：内部专业判断、临床或营养决策支持、探索性研究或其他；
- 完整 PICOS：人群、干预/暴露、对照、结局与时间点、计划纳入的研究设计；
- 截止日期、语种与地域要求；
- 是否已有方案注册、既有综述、已知关键研究或题录库；
- 预先指定的一个数据库，以及可获得的全文来源，按 `access-and-memory.md` 处理；
- 是否具备第二位筛选、提取或核对者；没有时披露单人流程并加强独立计算复核。

先形成研究方案。研究问题、纳排标准、主要结局、分析计划、亚组和敏感性分析应尽可能在看到结果前确定。若用户要求投稿或指南级产物，说明本流程只能作为前期证据包，仍需按目标期刊或机构要求扩展数据库和复核流程。

## 2. 选择信息源

预先选择一个最适合问题且实际可访问的数据库，并说明理由：

- 一般人体营养干预通常优先 PubMed，便于公开复现并获取完整题录和摘要；
- 若问题严格限定随机试验且具备访问条件，可选择 CENTRAL；
- 中国情境或中文干预可根据题目选择 CNKI、万方、VIP 或 SinoMed 中的一个；
- 长期安全性或罕见不良反应应选择更适合观察性或监管信号的数据源；如果单一来源明显不适合，就不强行做 Meta。

其他数据库、注册平台和引文追踪可用于解释遗漏风险或发现需要提示的记录，但不能悄悄并入后再继续声称是预定义的单数据库证据集。需要扩大范围时先修改方案并记录偏离。

## 3. 构建检索策略

### 3.1 概念块

先用 PICOS 定义完整纳排标准，再为数据库选择最少必要概念块。干预性问题常从人群与干预开始；对照、结局和研究设计在题名摘要中可能缺失或索引不足，不应机械加入检索式。每个概念块内部用 OR，块间用 AND。省略某个检索概念块不等于从 PICOS 纳排标准中删除该要素。

### 3.2 主题词与自由词并行

每个核心概念必须考虑：

- MeSH、Emtree 或数据库自身主题词；
- 通用名、旧名、拼写和连字符变体；
- 化学名、盐型、异构体、剂型；
- 植物拉丁名、部位、提取物和标准化标志物；
- 菌株、发酵或复配信息；
- 商品通用名和研究专用原料名；
- 中文名、俗名、英文缩写和可能的音译。

禁止 MeSH-only。对新近和未索引记录，题名摘要自由词是必要通道。

### 3.3 研究类型过滤

采用经过验证的高灵敏度过滤器；不要只依赖 `[pt]`。CENTRAL 不重复添加不必要的 RCT 或人类过滤。罕见不良反应和观察性研究避免过窄的研究设计过滤。

### 3.4 翻译与核验

针对选定数据库实际核验语法，记录平台、完整检索式、执行日期、限制、命中数和语法核验状态。L2-Research 默认检索全部年份，除非研究方案预先规定了有科学理由的时间窗；使用本 Skill 的 PubMed 脚本时应显式传入 `--all-years`，避免误用普通审计的近 10 年默认值。

- `[已核]`：已在目标数据库实际运行并检查语法/字段与结果；
- `[待核]`：按官方文档或通行语法准备，但尚未在目标平台运行。

PubMed 需要检查 Search Details/Query Translation，并用已知关键研究做召回测试。超过 E-utilities 可稳定取得的结果规模时，使用 EDirect 或按日期分段，并核对各分段总数、PMID 唯一性和完整性；不得把单批数量误写为总导出上限。

使用 `templates/search-strategy.md` 保存策略。

## 4. 检索、题录与全文

1. 用户或 Agent 在授权范围内运行检索，保存原始导出文件和日期。
2. 核对导出数等于命中数，按 PMID/DOI 去重，并人工识别同一研究的多篇报告；研究而非文章是分析单位。
3. 对全部命中完成题名摘要筛选和适用的全文筛选。筛选单位先是报告；后续将多篇报告链接到同一个底层试验、队列或研究。可以单人执行，但必须保存逐条判定与理由；有第二位评价者时独立核对，尤其是边界记录和全文排除。
4. 全文按 `full-text-access.md` 处理：先检查 PMCID，再跟随 DOI 到出版社正式页面，并核查合法开放仓储；也可通过机构订阅、馆际互借、作者稿或用户合法提供获得。
5. 分开记录 `access_status`（全文访问情况）、`data_sufficiency`（纳入/效应数据是否足够）、`appraisal_sufficiency`（评价条目能否判断）。摘要能否纳入由预先设定的方案、目标分析和实际数据充分性共同决定，不强制要求每篇都取得全文，也不得仅因摘要有数值就推定方法评价充分。关键效应数据或方法信息缺失时，不得猜补；可按方案进入敏感性分析或叙述综合，并明确相应限制。无全文访问不自动等于无数据，也不等于阴性结果。
6. 用 `templates/prisma-counts.md` 维护可核对的流程计数和排除原因。

## 5. 数据提取与偏倚风险

- 按研究而非报告提取，保留来源页码、表格和图号。
- 提取人群、基线营养状态、剂型、剂量、共干预、对照、随访、结局定义、资金和利益冲突。
- 按问题和研究设计使用匹配版本的 EAL QCC；可辅以适合该设计与领域的偏倚风险工具（例如 RCT 的 RoB 2、非随机干预的 ROBINS-I），但要说明各工具回答的问题，不把不同工具的分数混成一个等级。系统综述用 Review Articles QCC，并可结构化参考 AMSTAR 2/ROBIS；指南另行评价开发方法和证据到建议的链条。
- 有第二位评价者时独立核对关键结局；没有时至少使用第二种计算实现复核效应方向和数值，并把单人提取列为局限。无法从全文确认的数据标为缺失，不根据摘要或常识补齐。

## 6. 是否进行 Meta 分析

定量合并是回答问题的工具，不是检索后自动执行的默认步骤。**至少有两个独立且可比较的研究**是进行 Meta 的必要条件，不是充分条件；同一研究的多篇报告不能算作多个独立研究。没有可靠历史综述、EAL 结论为 III/IV/V、出现新研究或研究数量较多，均不能单独触发 Meta。先确认用户已同意此项深入工作（见快速审计的升级与同意流程），并在方案中说明该合并将回答哪个结局、为什么可能改变证据判断或决策、所需数据是否足够及预期时间。

之后判断人群、干预/暴露、对照、结局定义、时间点、研究设计和效应估计是否足以合并。先说明重要差异；RCT 与观察性研究分别综合，不能为了增加研究数而合并。观察性研究之间也须检查设计、暴露测量、混杂控制和时间关系是否可比。若合并不能回答预定问题、研究不可比较、关键数据不足或预期结果不会改变理解，则改用结构化叙述综合。摘要资料可否用于特定分析仍由预设方案和数据充分性决定；摘要通常不足以支持需要全文信息的完整偏倚评价。

- 二分类优先报告 RR 或 RD；病例对照可用 OR；向用户同时给绝对效应。
- 连续结局同单位用 MD，不同量表才用 SMD。
- 随机效应模型默认考虑 REML；小研究数时对 τ² 和区间保持谨慎。
- k<10 不做或不解释 Egger 为“无发表偏倚”。
- 预先设定亚组；事后亚组标记为探索性并使用交互检验。
- 研究数少、数据无法转换或异质性无法解释时，采用结构化叙述合成，不为生成森林图而强行合并。

可使用：

- `templates/data-extraction-binary.csv`
- `templates/data-extraction-continuous.csv`
- `scripts/meta_analysis.R`：本机 R + metafor 的首选计算与原生森林图/漏斗图；
- `scripts/meta_compute.py`：本机 R 不可用时的 Python 独立复现与静态报告；
- `templates/metafor-runner.template.html`：R/Python 均不可执行时的在线 webR + metafor；
- `templates/metafor-runner-offline.template.html` 与 `webr-offline/`：在线 webR 不可达时的完全离线 webR + metafor。

运行前完整读取 `statistical-engine-routing.md`，不得跳过可用的本机 R 而把 Python 冒充为 metafor；也不得把敏感研究数据上传到随机第三方在线 R 服务。脚本结果必须与原始数据、效应方向和至少一个独立计算进行核对。统计引擎不能替代临床可合并性判断。

## 7. EAL 结论与报告边界

逐结局综合时完整读取 `eal-methodology.md`。按匹配研究设计评价单项研究，区分 QCC、效应方向、效果大小、结论支持程度、用户匹配度和决策价值。RCT 与观察性研究先分开呈现，再解释其结果是否相互支持、差异是否可能来自设计、偏倚、暴露或结局测量、随访和目标人群。不能从单篇质量符号、研究篇数或统计显著性投票直接换算 EAL 结论等级。

历史基座与新增记录应按相同 PICOS、结局定义、研究设计和效应尺度逐项对照。先将报告去重并映射到独立研究/队列，查明新增记录是否为既有研究的后续或重复报告；不得把综述汇总值与其纳入的原始研究当成独立证据重复计数。判断新旧结果是否冲突时，检查点估计和区间、方向、临床重要性、一致性、纳入研究变化、偏倚风险、适用性、分析选择及勘误/撤稿等出版状态。统计显著与否一变，不足以证明冲突；若新证据改变了估计、重要性判断或结论支持度，说明改变来自何处，并更新逐结局 EAL 评价；若差异能由范围或方法解释，分别报告适用边界。不能消解且会改变行动的冲突应作为核心不确定性呈现，必要时建议独立复核或按用户授权升级，而非挑选单一有利结果。

正式结论等级只在证据体边界、相关结局和方法表条件满足时给出。证据范围未完成、关键研究状态未明、资料不足或 QCC/结论表适用规则未核定时，保留明确的 `incomplete` / `preliminary` 状态和空等级；EAL V 仅表示已评价范围内没有直接支持或反驳该具体结论的证据，不表示流程不完整或全文未取得。报告评级依据及版本、各结局的证据数量和质量、一致性、临床影响、可推广性、局限，以及哪些新增证据会改变结论。

输出至少包括：

- 方案与偏离记录；
- 指定数据库、完整检索式、日期、命中与导出数；
- PRISMA 计数；
- 纳入研究与排除全文清单；
- 数据提取表和偏倚风险；
- 合成结果、敏感性分析和局限性；
- 逐关键结局的综合结果、EAL 结论评级或未评级原因，以及大白话总结；
- 哪些证据缺口会改变结论。

报告标题使用“基于【数据库】和本轮可得资料的证据合成”。结论必须说明单数据库、使用摘要或全文的实际范围、单人/双人筛选以及未检索注册平台和灰色文献的影响。资料是否能纳入取决于预设纳入规则与所需信息是否足够，不以全文访问状态单独决定。缺失关键数据、研究不可比较或方法不适合合并时，交付结构化叙述综合，不为生成森林图而降低标准。
