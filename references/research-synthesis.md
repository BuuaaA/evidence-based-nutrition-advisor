# 单数据库 Meta 证据合成

用于目前没有可靠综合结论的问题：现有综述缺失、过时、方法不可靠，或新研究可能改变旧结论。目标是在一个预先指定的数据库内，完整识别研究并利用可获得全文重新提取、评价和合并，得到范围透明、可以复核的当前估计。

这不是发表级系统综述。单数据库可能遗漏其他数据库和未发表研究；全文不可得也会造成选择性证据缺失。标题、方法和结论必须同时写明数据库名称、检索截止日期、筛选方式和全文可得性，不能使用“全面检索”“完整系统综述”或“发表级 Meta”等表述。

## 术语约定：PICO 与 PICOS

本 Skill 用 **PICOS** 作为完整纳排框架的简写。其方法学含义与 [Cochrane Handbook 第 3 章](https://training.cochrane.org/handbook/current/chapter-03) 一致：综述问题用 PICO 表达，预设纳排标准还必须明确允许的研究类型。换言之，PICO 可以描述临床问题，但不能替代 `S`（Study design）；数据库检索是否加入研究设计过滤器，则应按召回率、索引状态和已验证过滤器单独决定。

## 0. Meta 类型确认

用户提出“Meta 分析”“能不能重新合并”，但未明确是评价既有综述还是重新提取原始研究时，必须先问：

> 您是希望核查已有 Meta 分析，还是基于一个预先指定的数据库和可获得全文，重新完成一次 Meta 证据合成？

在用户选择之前不先展示现有 Meta 结论，避免把“找到并总结一篇 Meta”和“重新提取原始研究并合并”混为一谈。

- 选择“现有 Meta 的证据审计” → 返回专业证据审计，评价检索覆盖、纳入研究、重复数据、RoB、统计模型、异质性、发表偏倚、GRADE、更新程度和利益冲突；不执行新的定量合并。
- 选择“单数据库 Meta 证据合成” → 继续本文件流程。

如果用户已经明确说“审计这篇/这些既有 Meta”或“基于某数据库和可获得全文重新合并”，选择已经完成，不重复询问。

## 1. 启动前确认

确认以下事项；用户已经说明的不要重复问：

- 需要回答的证据空白，以及为什么现有结论不可靠或不够新；
- 用途：内部专业判断、临床或营养决策支持、探索性研究或其他；
- 完整 PICOS：人群、干预/暴露、对照、结局与时间点、计划纳入的研究设计；
- 截止日期、语种与地域要求；
- 是否已有方案注册、既有综述、已知关键研究或题录库；
- 预先指定的一个数据库，以及可获得的全文来源，按 `access-and-memory.md` 处理；
- 是否具备第二位筛选、提取或核对者；没有时披露单人流程并加强独立计算复核。

先形成研究方案。研究问题、纳排标准、主要结局、分析计划、亚组和敏感性分析应尽可能在看到结果前确定。若用户要求投稿或指南级产物，说明本流程只能作为前期证据包，仍需按目标期刊或机构要求扩展数据库和复核流程。

## 2. 选择信息源

预先选择一个最适合问题且实际可访问的数据库，并说明理由：

- 一般人体营养干预通常优先 PubMed，便于公开复现并获取完整题录和摘要；
- 若问题严格限定随机试验且具备访问条件，可选择 CENTRAL；
- 中国情境或中文干预可根据题目选择 CNKI、万方、VIP 或 SinoMed 中的一个；
- 长期安全性或罕见不良反应应选择更适合观察性或监管信号的数据源；如果单一来源明显不适合，就不强行做 Meta。

其他数据库、注册平台和引文追踪可用于解释遗漏风险或发现需要提示的记录，但不能悄悄并入后再继续声称是预定义的单数据库证据集。需要扩大范围时先修改方案并记录偏离。

## 3. 构建检索策略

### 3.1 概念块

先用 PICOS 定义完整纳排标准，再为数据库选择最少必要概念块。干预性问题常从人群与干预开始；对照、结局和研究设计在题名摘要中可能缺失或索引不足，不应机械加入检索式。每个概念块内部用 OR，块间用 AND。省略某个检索概念块不等于从 PICOS 纳排标准中删除该要素。

### 3.2 主题词与自由词并行

每个核心概念必须考虑：

- MeSH、Emtree 或数据库自身主题词；
- 通用名、旧名、拼写和连字符变体；
- 化学名、盐型、异构体、剂型；
- 植物拉丁名、部位、提取物和标准化标志物；
- 菌株、发酵或复配信息；
- 商品通用名和研究专用原料名；
- 中文名、俗名、英文缩写和可能的音译。

禁止 MeSH-only。对新近和未索引记录，题名摘要自由词是必要通道。

### 3.3 研究类型过滤

采用经过验证的高灵敏度过滤器；不要只依赖 `[pt]`。CENTRAL 不重复添加不必要的 RCT 或人类过滤。罕见不良反应和观察性研究避免过窄的研究设计过滤。

### 3.4 翻译与核验

针对选定数据库实际核验语法，记录平台、完整检索式、执行日期、限制、命中数和语法核验状态。

- `[已核]`：已在目标数据库实际运行并检查语法/字段与结果；
- `[待核]`：按官方文档或通行语法准备，但尚未在目标平台运行。

PubMed 需要检查 Search Details/Query Translation，并用已知关键研究做召回测试。超过 E-utilities 可稳定取得的结果规模时，使用 EDirect 或按日期分段，并核对各分段总数、PMID 唯一性和完整性；不得把单批数量误写为总导出上限。

使用 `templates/search-strategy.md` 保存策略。

## 4. 检索、题录与全文

1. 用户或 Agent 在授权范围内运行检索，保存原始导出文件和日期。
2. 核对导出数等于命中数，按 PMID/DOI 去重，并人工识别同一研究的多篇报告；研究而非文章是分析单位。
3. 对全部命中完成题名摘要筛选和全文筛选。可以单人执行，但必须保存逐条判定与理由；有第二位评价者时独立核对，尤其是边界记录和全文排除。
4. 全文通过开放获取、机构订阅、馆际互借、作者稿或用户合法提供获得。
5. 无法获得的全文单独记录为“待获取/无法获取”，说明尝试过程；不得仅凭摘要提取效应量或完成偏倚评价，也不得把这些研究悄悄算作阴性结果。
6. 用 `templates/prisma-counts.md` 维护可核对的流程计数和排除原因。

## 5. 数据提取与偏倚风险

- 按研究而非报告提取，保留来源页码、表格和图号。
- 提取人群、基线营养状态、剂型、剂量、共干预、对照、随访、结局定义、资金和利益冲突。
- RCT 使用适合的 RoB 2 结构；非随机干预研究考虑 ROBINS-I；系统综述用 AMSTAR 2/ROBIS；诊断或其他问题选用相应工具。
- 有第二位评价者时独立核对关键结局；没有时至少使用第二种计算实现复核效应方向和数值，并把单人提取列为局限。无法从全文确认的数据标为缺失，不根据摘要或常识补齐。

## 6. 是否进行 Meta 分析

只有研究在临床和方法上足够相似时才合并。先解释人群、剂型、剂量、结局定义和时间点差异，再选择模型。

- 二分类优先报告 RR 或 RD；病例对照可用 OR；向用户同时给绝对效应。
- 连续结局同单位用 MD，不同量表才用 SMD。
- 随机效应模型默认考虑 REML；小研究数时对 τ² 和区间保持谨慎。
- k<10 不做或不解释 Egger 为“无发表偏倚”。
- 预先设定亚组；事后亚组标记为探索性并使用交互检验。
- 研究数少、数据无法转换或异质性无法解释时，采用结构化叙述合成，不为生成森林图而强行合并。

可使用：

- `templates/data-extraction-binary.csv`
- `templates/data-extraction-continuous.csv`
- `scripts/meta_analysis.R`：本机 R + metafor 的首选计算与原生森林图/漏斗图；
- `scripts/meta_compute.py`：本机 R 不可用时的 Python 独立复现与静态报告；
- `templates/metafor-runner.template.html`：R/Python 均不可执行时的在线 webR + metafor；
- `templates/metafor-runner-offline.template.html` 与 `webr-offline/`：在线 webR 不可达时的完全离线 webR + metafor。

运行前完整读取 `statistical-engine-routing.md`，不得跳过可用的本机 R 而把 Python 冒充为 metafor；也不得把敏感研究数据上传到随机第三方在线 R 服务。脚本结果必须与原始数据、效应方向和至少一个独立计算进行核对。统计引擎不能替代临床可合并性判断。

## 7. GRADE 与结论

正式评级前完整读取 `grade-methodology.md`。GRADE 按结局和证据体评价，不给单篇研究打一个总等级。明确决策阈值、绝对效应、五个降级域和避免重复扣分。

输出至少包括：

- 方案与偏离记录；
- 指定数据库、完整检索式、日期、命中与导出数；
- PRISMA 计数；
- 纳入研究与排除全文清单；
- 数据提取表和偏倚风险；
- 合成结果、敏感性分析和局限性；
- 逐关键结局 GRADE 与大白话总结；
- 哪些证据缺口会改变结论。

报告标题使用“基于【数据库】和可获得全文的 Meta 证据合成”。结论必须说明单数据库、全文缺失、单人/双人筛选以及未检索注册平台和灰色文献对结果的可能影响。缺失全文较多、效应数据不足或研究不可合并时，交付结构化叙述合成或明确的“不足以可靠合并”，不为生成森林图而降低标准。
