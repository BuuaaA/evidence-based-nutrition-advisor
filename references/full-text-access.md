# 全文访问判定与记录

PubMed 是题录和摘要入口，不是“全文是否存在或是否免费”的最终判定页。PubMed 页面没有全文按钮、RIS 中只有摘要，均不得直接记为“全文缺失”。

## 1. 何时执行

- L1-Quick 通常不逐篇获取全文；它不能报告“某篇全文不可得”，只能说明尚未进行完整全文审计。
- L1-Audited 或 L2 中，题名摘要筛选为 `include` 的记录必须完成下列访问核查。可先批量生成访问候选，再并行打开；不得让一个站点的超时阻塞其他记录。

## 2. 法律允许范围内的访问顺序

1. 从 RIS 提取 PMID、PMCID 和 DOI；`scripts/ris_screening_draft.py` 会把候选链接写入 `access_candidates`。
2. 有 PMCID 时先打开 PubMed Central 的 HTML 或 PDF。
3. 有 DOI 时必须跟随 `https://doi.org/...` 到出版社正式页面，检查网页全文、PDF 和开放获取标识。不能停在 PubMed 摘要页。
4. 正式页面未提供全文时，再检查合法的开放仓储或作者稿，例如 Europe PMC、机构知识库或出版社允许的作者稿入口。
5. 若当前环境有机构订阅，或用户合法提供了文件，可以使用；不得绕过付费墙、访问控制或网站条款。
6. 在 `full_text_access_attempts` 记录实际尝试的入口与结果，在 `access_checked_at` 记录核查日期。

## 3. `full_text_status` 受控词表

| 状态 | 含义 | 是否算作已全文评估 |
|---|---|---|
| `obtained` | 已合法取得并实际阅读全文或完成所需评估 | 是 |
| `subscription_obtained` | 通过授权订阅取得并评估 | 是 |
| `user_supplied` | 用户合法提供并完成评估 | 是 |
| `open_access_found` | 已找到免费全文入口，但尚未阅读全文 | 否；属于待办，不能称为缺失，也不能最终出卡 |
| `paywalled` | 已检查 PMC、DOI/出版社和适当开放仓储，仅发现需授权全文 | 否 |
| `retrieval_failed` | 已找到入口，但经过记录的重试仍因网络、服务器或文件错误无法取得 | 否 |
| `not_found` | 已按上述顺序核查，仍未找到合法全文入口 | 否 |
| `abstract_only` | 旧日志兼容状态；新日志不得直接使用 | 否 |

状态描述的是本轮实际访问结果，不是论文质量。`open_access_found` 必须继续到“取得并评估”，或在确有失败时改成带访问记录的 `retrieval_failed`。生成器会拒绝把它算作“全文缺失”。

## 4. 报告规则

- 只有 `paywalled`、`retrieval_failed` 或 `not_found` 且记录了尝试与日期，才可进入“尚未取得全文”计数。
- 不得仅凭摘要提取效应量、完成偏倚风险评价或写“全文已评估”。
- 对外说明是“本轮未取得全文”，不要写成“这篇文章没有全文”或“不是开放获取”，除非来源明确支持该事实。
- 缺失记录必须显示对结论和确定性可能造成的影响，并允许用户补充合法全文后重评。
