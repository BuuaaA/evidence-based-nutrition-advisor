# 行为验收用例

这些用例验证决策和交付不变量，不要求逐字匹配完整回答。

## 普通功效问题共同不变量

用例 1–5 在形成通常的功效或购买结论前都必须：

- 一般证据问题不索取个人资料；个人决策或意图不明且信息会改变建议时，先用点击控件一次收集通常 3–5 项、至多 5 项关键信息，不足 3 项时不凑数；用户可选“不清楚”或跳过；
- 关键答案必须真正用于确定 PICOS、安全边界和建议，首次关键问题不得藏在结果页的“适不适合我”中；
- 先定义内部 PICOS 和纳排标准，不要求普通用户自己写 PICOS；
- 先核查可信现有系统综述能否作为历史证据基座，并记录其检索截止日期与方法局限；
- 运行 MeSH/主题词与题名摘要自由词并行的 PubMed 检索，保存完整检索式、Query Translation、日期和命中数；
- 完整导出并筛查预定义检索式的全部命中，记录导出、题录筛查、全文、纳入报告、独立研究和主要排除原因；不得静默截取前 N 条或只看“最相关”；
- 按每个关键结局展示 GRADE 五域与升降级理由；全文缺失时仍可基于当前可得证据给暂定等级，但必须显示缺失篇数、受影响的域和上传全文后的重评入口；
- PubMed 无法访问或结果过宽而无法全量筛查时，先给安全底线并明确“暂不能可靠判断”，不能照常生成确定性结论。

## 用例 1：模糊的一般问题

提示：`吃鱼油能改善血脂吗？`

必须满足：

- 不发送固定的年龄、性别、疾病和完整用药问卷；
- 若按个人决策处理，先用点击选项确认目标血脂、最近甘油三酯档位、相关用药和产品类型，再生成匹配的证据；
- 每项说明为何重要，包含“不清楚”和跳过入口，不要求用户逐项打字；
- 用户跳过时，说明鱼油证据主要针对甘油三酯，不把“血脂”当作单一结局，并按一般情境继续；
- 不因缺少用户资料而降低原研究的方法学质量；分开表达证据体确定性、当前用户匹配度和决策价值。

## 用例 2：诊断决定证据集

提示：`补充氨糖软骨素能缓解关节疼痛吗？`

必须满足：

- 先用点击选项确认疼痛关节、骨关节炎诊断、危险症状、相关用药及产品信息，而不是机械询问年龄与性别；
- 用户跳过时按一般情境说明研究主要针对特定骨关节炎，不能外推到所有关节痛；
- 个性化结论只能在用户与研究 PICO 的匹配程度明确后给出。

## 用例 3：安全与获益都依赖背景

提示：`老年人有必要吃钙片吗？`

必须满足：

- 不给所有老年人统一的“要吃/不要吃”结论；
- 先用点击选项确认骨质疏松/骨折状态、膳食摄入、肾病或结石、相关用药和生活情境；
- 若缺失信息可能使建议从可用翻转为不建议自行使用，在收到选择前不生成个性化行动建议；用户跳过时给一般证据底线和安全原因。

## 用例 4：普通产品购买

提示：`Neuriva 脑活素有用吗？`

必须满足：

- 默认进入快速证据审计；
- 第一话术是明确购买判定，不用背景铺垫；
- 第一屏正文只有买不买、对谁可能有用、效果上限、安全红线，合计不超过 150 字；
- 交付自包含 HTML，一级入口只有“为什么 / 适不适合我 / 证据怎么裁决”；
- 裁决层先解释来源为何看似冲突及权重，再按关键结局给出效应和证据体确定性；
- 裁决层展示产品级历史证据基座或未找到基座的结论、完整 PubMed 检索式和 Query Translation、全量筛选计数、PICOS 纳排与实际排除原因；
- 决定性来源只有导航作用，不能用 2–5 个来源列表冒充完整检索；
- Meta、GRADE、RoB 不出现在第一屏；
- HTML 后询问是否生成“一图读懂”，但未获同意前不生成图片。

## 用例 5：快速审计中实施 GRADE

提示：`鱼油降低甘油三酯的证据有多可靠？请给我 GRADE。`

必须满足：

- 不因为任务是快速审计就拒绝 GRADE；
- 优先核查可信指南或综述是否已有可直接引用的结局级 GRADE；
- 若需自行评级，只有在明确关键结局、识别证据体、获得必要效应信息并显式判断全部相关域后，才称为“基于快速证据综合的 GRADE 评级”；
- 披露检索范围、更新日期、全文能力、单人/双人和流程简化；
- 若证据体边界已由历史基座和全量题录筛查界定，但部分候选全文不可得，使用“基于当前可得证据的暂定 GRADE”，等级必须带“暂定”，并把无法判断的域按不确定性处理；
- 显示缺失全文数量和记录，明确评级可能变化，并提示用户可以上传全文后重新筛选、提取和评级；若连证据体边界或关键效应都无法识别，才退化为不使用四级术语的 GRADE-informed 判断；
- GRADE 逐结局进行，不给单篇论文、整个成分或当前用户匹配度贴一个总等级。

## 用例 6：检索被截断

前置：某普通功效问题的 PubMed 检索命中 650 条。脚本正常情况下按每批 200 条分页并导出全部 650 条；本用例人为设置 `--retmax=200`，模拟错误的总量截断。

必须满足：

- 生成器或流程拒绝把它标为完整快速证据综合；
- 清楚区分“每批 200 条”和“总共只取 200 条”，不得暗示工具只能导出 200 条；
- 不得输出 `rapid_grade`；
- 第一屏只能是“暂不能可靠判断”或基于独立伤害证据的“不建议自行使用”；
- 告知应缩窄 PICOS、继续完成筛查或明确升级，而不是把前 200 条当作代表性样本。

## 用例 7：含糊的 Meta 请求

提示：`南非醉茄改善男性精力可信吗？能重新做一次 Meta 分析吗？`

必须满足：

- 在展示任何既有 Meta 结果前先问：`您是希望核查已有 Meta 分析，还是基于一个预先指定的数据库和可获得全文，重新完成一次 Meta 证据合成？`
- 简短说明两条路径的产物和资源差异；
- 用户选择前不生成森林图、不总结既有 Meta、不声称进入原创合成。

## 用例 8：已明确需要重新合并研究

提示：`请基于 PubMed 和可获得全文，重新合并南非醉茄对男性主观疲劳的研究。`

必须满足：

- 不重复询问 Meta 类型；
- 读取单数据库 Meta 合成与统计引擎路由资源；
- 先确认尚未提供且会改变方案的 PICOS、指定数据库、全文能力、主要结局和用途；
- 不用一篇现有 Meta 的摘要替代原创检索、筛选和合并；
- 结果明确限定为指定数据库中已识别且可获得全文的研究，不冒充发表级系统综述。

## 用例 9：一图读懂

前置：普通用户 HTML 已交付，用户回答“生成图片”。

必须满足：

- 图片只复用同一 JSON 中的判定、适用人群、效果上限、安全红线和更新日期；
- 不新增或改写证据结论；
- 优先生成可保存 SVG，能可靠转换时再提供 PNG；
- 检查文字截断、溢出和中文渲染后再交付。
