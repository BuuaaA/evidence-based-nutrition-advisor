# evidence-based-nutrition-advisor V1.0.1 使用指南

这个 Skill 的专业深度由“任务”决定，而不是由用户的职业头衔决定。普通用户也可以要求详细证据；专业人员问一个购买问题时，也可以直接使用快速模式。

## 1. 普通消费者：判断要不要买

### 适合的问题

- 某种补充剂、营养素或功能成分有没有用；
- 两个产品哪一个更值得；
- 某条广告、主播或博主的说法是否可信；
- 针对睡眠、精力、血脂、记忆等目标，营养上有哪些优先路径。

### 最好提供什么

- 真正想改善的目标；
- 产品名称、配方、每份剂量和用法；
- 若涉及本人：会改变安全性的疾病、处方药、孕哺或关键化验。

无需填写完整健康问卷。面对模糊的个人决策问题，Skill 会先用“决策翻转测试”筛出通常 3–5 项、至多 5 项关键信息，并尽量让你直接点击选项；只有答案会改变购买判定、适用证据集、安全红线或是否需要医学评估时才问。如果真正关键的只有 1–2 项，就不会为凑数多问。年龄和性别不是固定必问项；你也可以选择“不清楚”或跳过，先看一般结论。

### 推荐提示词

```text
使用 $evidence-based-nutrition-advisor。
我想改善【目标】，正在考虑【产品/成分、剂量】。
请先告诉我值不值得买、对谁可能有用、效果上限和安全红线，再把研究依据放在可展开部分。
```

### 你会得到什么

- 第一眼可读的购买判定；
- 谁可能受益、谁不适合自行使用；
- 实际效果上限，而不是只给相对百分比；
- “为什么 / 适不适合我 / 证据怎么裁决”三个展开层；
- 在裁决层看到来源为何结论不同、为何赋予不同权重，以及各关键结局的证据体确定性；
- 看清确定性结论是引用已有 GRADE、基于快速证据综合重新 GRADE、全文缺失时的暂定 GRADE，还是证据体无法界定时的 GRADE-informed 判断；
- 查看历史系统综述基座、完整 PubMed 检索式与 Query Translation、命中及全量筛选计数、PICOS 纳排、主要排除原因和逐结局 GRADE 五域；
- 在可写文件的环境中，一个离线可打开的 HTML。

## 2. 本人或家属代问：增加个性化但保护隐私

### 使用原则

- 代问家人、朋友或患者时，默认只在当前会话临时使用资料；
- 不读取本人的档案去推断另一个人；
- 如需长期追踪他人，应建立独立、去身份化档案，并确认你有权保存这些信息；
- 出现进行性症状、严重异常、孕哺、肝肾疾病、手术或处方药相互作用时，先处理安全问题。
- 如果安全信息不足以给个人行动建议，Skill 会先用点击选项收集关键信息；用户跳过时仍交付一般证据底线，并说明暂定情境和无法个性化的部分。

### 推荐提示词

```text
使用 $evidence-based-nutrition-advisor。我替家人临时咨询，不要保存资料。
对象是【年龄段/相关状态】，目标是【结局】，正在使用【药物/补充剂】。
请先用点击选项询问真正会改变建议的关键信息，通常 3 至 5 项、至多 5 项；如果不足 3 项，不要凑数。
```

### 长期追踪

只有你明确说“请建立档案/记住/长期追踪”后才会启用。开始试用前应定义基线、目标指标、观察期、同期变化和停止条件；单人的前后变化不能证明因果。

## 3. 营养师、医生、药师：专业快速核查

### 适合的问题

- 指南、系统综述和新 RCT 是否一致；
- 某结论是否适用于特定患者群体、基线状态、剂型或剂量；
- 效应量是否达到临床或决策重要性；
- 一篇 Meta 的检索、偏倚与统计方法是否可信；
- 产品研究能否迁移到当前配方。

### 推荐提示词

```text
使用 $evidence-based-nutrition-advisor 做专业证据审计。
问题：【PICOS 或临床问题】。
请报告检索日期、最佳指南/综述的检索截止日期、关键效应量与区间、偏倚风险、确定性、适用边界和冲突归因。
没有足够全文时不要声称完成正式 RoB、AMSTAR 2 或 GRADE。
```

### 你会得到什么

- PICOS 和来源角色拆分；
- 证据体确定性、当前用户匹配度与决策价值的分离；
- 指南开发质量与推荐/证据等级的区分；
- 系统综述关键方法域的快速审计；
- 以可信综述作为历史证据基座，并完整导出和筛查其截止日期之后的 PubMed 更新检索命中；无合格综述时从头完成范围可管理的 PubMed 证据普查；
- 对人群、剂型、剂量、结局、随访和利益冲突的解释。
- 证据体和方法信息充分时，可在专业快速核查中实施结局级 GRADE；不要求先升级为原创系统综述。

快速 GRADE 仍须逐结局判断所有相关域，并披露检索范围、完整检索式、Query Translation、筛选流程、更新日期、全文能力、单人/双人和其他简化。若题名摘要筛查完整、证据体边界明确但部分全文不可得，输出暂定 GRADE，并显示缺失记录和上传提示；若检索边界、证据体或关键效应无法识别，才降级为不使用四级等级的 GRADE-informed 判断。

普通功效问题不得只看搜索结果前几条。检索被截断、筛选未完成或 PubMed 不可访问时，Skill 会先给安全底线并标为“暂不能可靠判断”，而不是继续输出看似确定的购买结论。

## 4. 研究人员与专业用户：单数据库 Meta 证据合成

### 先区分两种任务

- **现有 Meta 的证据审计**：评价别人已经完成的综述，不重新合并数据；
- **单数据库 Meta 证据合成**：针对没有可靠综合结论的问题，在一个预先指定的数据库内完整检索和筛选，只用可获得全文重新提取、评价和合并。

如果提示词含糊，Skill 会先要求选择，不会用一篇现有 Meta 的摘要冒充重新合并。

### 推荐提示词

```text
使用 $evidence-based-nutrition-advisor，基于【指定数据库】和可获得全文，
重新合并【干预】对【结局】的研究。计划纳入【研究设计】，截止日期【日期】。
请先形成 PICOS、主要结局和分析方案；结果写明数据库、缺失全文和单人/双人流程，
不要称为全面系统综述或发表级 Meta。
```

### 关键预期

- 在预先指定的数据库中实际核验检索式，主题词与自由词并行；
- 研究而非文章作为分析单位；
- 正式项目需要双人筛选/核对和全文证据；
- 临床不可合并时采用叙述合成，不为森林图强行合并；
- 统计引擎、软件版本、包版本、命令、输入哈希和输出都应可复现；
- 只从可核查全文提取数据；数据库或全文限制必须进入标题、GRADE 和结论边界。

## 5. 科普、媒体与产品团队：宣称审计

### 适合的问题

- 产品页是否把体外、动物或机制研究说成了人体临床效果；
- 引用的论文是否研究了同一人群、剂型、剂量和产品；
- “统计学显著”是否被包装成用户可感知的收益；
- 某句话怎样改写才与当前证据相称。

### 推荐提示词

```text
使用 $evidence-based-nutrition-advisor 审计下面的产品宣称。
对每条宣称给出：原文、证据链层级、引用是否匹配、主要外推、可支持到什么程度、建议改写。
不要仅凭期刊名或影响因子判断研究质量。

【粘贴宣称、产品页和引用】
```

### 你会得到什么

- 宣称与 PICOS 的逐条映射；
- 机制、暴露、靶点、替代指标、临床结局和产品可迁移性的分层；
- 证据确定性与商业决策价值的分离；
- 更准确、风险更低的表达建议。

## 平台能力差异

| 能力 | 只有聊天 | 可写本地文件 | 可联网检索 | 有 R/Python | 有受限数据库 |
|---|---|---|---|---|---|
| 快速结论 | 只能基于已提供资料并标明限制 | 支持生成产物 | 普通功效结论的 PubMed 最低流程所必需 | 非必需 | 非必需 |
| 单文件消费者报告 | 用内联结构降级 | 支持 HTML/SVG | 可带来源链接 | Python 可自动生成 | 非必需 |
| 专业更新扫描 | 只能基于已提供资料 | 可保存策略 | 支持 PubMed/官方来源 | 可自动去重 | 可扩大覆盖 |
| 单数据库 Meta 证据合成 | 仅能规划或审计资料 | 可保存全套产物 | 支持公开检索 | 支持计算和复现 | 非必需，但可用于扩大全文来源 |

Skill 不会把宿主不具备的能力假装成已经完成。
