# evidence-based-nutrition-advisor V1.0.1 案例展示

以下案例用于展示 Skill 如何路由任务和组织交付，不应当作针对任何个人的当前医疗建议。真实使用时应重新检索截至当日的证据，并结合产品版本、剂量、疾病、用药和地区监管状态。

[在线查看 14 个行为验收用例的结果说明图](https://buuaaa.github.io/evidence-based-nutrition-advisor/examples/consumer-answer-demo.html)。该静态图库属于 V1 GRADE 流程的历史演示，不代表 V2 EAL 流程；V2 的当前验收规则见 `tests/behavior-cases.md`。

## 案例 1：模糊的关节疼痛问题

**用户提示**

```text
使用 $evidence-based-nutrition-advisor：补充氨糖软骨素能缓解关节疼痛吗？
```

**路由**：快速证据审计；先用不超过 5 项的点击选择判断是否与膝骨关节炎证据集匹配。

**交付重点**

- 证据生成前一次点击确认疼痛关节、是否确诊、危险症状、相关用药和配方信息；
- 用户跳过时，按一般情境说明证据主要针对已确诊膝骨关节炎，不能外推到所有关节痛；
- 把疼痛与功能分开评价，并用临床重要阈值解释统计差异；
- 后台复用历史系统综述基座，再完整导出和筛查 PubMed 更新检索的 7 条命中；
- V1 历史演示展开层曾显示检索式、Query Translation、筛选计数、PICOS 纳排和 GRADE 五域；V2 应显示适用 QCC 评价、逐结局 EAL 状态及其依据。

**可查看产物**

- [结构化输入 JSON](../examples/cases/glucosamine-chondroitin/answer.json)
- [详细 HTML 结果](../examples/cases/glucosamine-chondroitin/answer.html)
- [14 个用例可视化画廊](https://buuaaa.github.io/evidence-based-nutrition-advisor/examples/consumer-answer-demo.html)

示例来自仓库的行为测试与证据包，用来验证交付结构；真实回答必须刷新检索日期并核对诊断、剂型和剂量。

## 案例 2：模糊问题的点击式个性化

**用户提示**

```text
吃鱼油能改善血脂吗？
```

**路由**：快速证据审计；个人意图尚不明确。

**预期交付**

1. 先用 4 项点击选择确认目标血脂、最近甘油三酯档位、相关用药和产品类型；
2. 收到选择后据此确定 PICOS，再运行 PubMed 检索和证据综合；
3. 用户跳过时才按一般情境说明鱼油主要作用于甘油三酯，不把“血脂”当成单一结局；
4. 不先发送年龄、性别和完整病史问卷；
5. 分开表达该结局的证据体确定性、当前用户匹配度和最终决策价值。

## 案例 3：用户含糊地要求重新做 Meta

**用户提示**

```text
南非醉茄改善男性精力可信吗？能重新做一次 Meta 分析吗？
```

**路由**：先做 Meta 意图分流，不展示任何证据结论。

**Skill 的关键回应**

```text
您是希望核查已有 Meta 分析，还是基于一个预先指定的数据库和可获得全文，重新完成一次 Meta 证据合成？
```

随后只说明两条路径的交付物和证据边界。用户选择前不生成森林图，不把找到一篇 Meta 等同于重新提取原始研究并合并。

## 案例 4：营养师核查指南冲突

**用户提示**

```text
使用 $evidence-based-nutrition-advisor 做专业审计：
为什么两份指南对某营养干预的推荐不同？请比较目标人群、剂量、结局、检索截止日期、推荐强度和利益冲突。
```

**路由**：专业证据审计。

**预期交付**

1. 判断是表面冲突、时间冲突、推荐阈值冲突、方法冲突还是真正证据冲突；
2. 分开报告证据确定性与推荐强度；
3. 指出各结论分别在什么条件下成立；
4. 只有现有综合结论仍不可靠且重新合并可能改变决策时，才考虑单数据库 Meta 证据合成。

V1 案例中的快速 GRADE 路由已弃用。V2 的 L1-Quick 不做本轮 EAL 自评级；完整 EAL 结论评价只在证据体、关键结局、资料与方法规则满足条件时执行。全文未取得不自动排除摘要数据，按预设方案区分数据充分性与方法评价充分性。

[查看完整的专业证据展示：老年人补钙](../examples/cases/calcium-older-adults/professional-evidence.md)。

## 案例 5：产品团队审计宣传引用

**用户提示**

```text
使用 $evidence-based-nutrition-advisor 审计以下宣称：
“成分 X 能穿过血脑屏障，所以每天服用能改善记忆。”
请判断引用证据到达了证据链哪一层，并给出不夸大的改写。
```

**路由**：宣称审计。

**预期交付**

- “能到达某组织”最多支持靶点可达性，不自动证明临床效果；
- 检查口服剂量、人体暴露、实际研究结局和当前产品可迁移性；
- 若缺少直接人体临床证据，改写必须停留在机制或研究信号层面。

## 案例 6：单数据库 Meta 证据合成

**用户提示**

```text
使用 $evidence-based-nutrition-advisor，基于 PubMed 和可获得全文，
重新合并某干预对某结局的研究。纳入随机对照试验，截止 2026-08-01。
```

**路由**：单数据库 Meta 证据合成，不再重复询问 Meta 类型；先完善 PICOS、主要结局、全文可得性和分析方案。

**预期交付链**

```text
研究方案 → 单数据库完整检索 → 原始导出 → 去重 → 全量筛选 → 全文与排除原因
    → 按研究提取 → RoB → 临床可合并性判断 → Meta/叙述合成
    → 敏感性分析 → 逐结局 EAL 结论评价 → PRISMA 与完整复现记录
```

结果标题写明数据库及本轮可得资料范围。全文缺失、摘要数据使用、单人筛选或提取分别披露；摘要数据是否纳入由预设方案和信息充分性决定。该结果用于回答缺少可靠综合结论的问题，不称为全面系统综述或发表级 Meta。

## 案例 7：长期追踪个人试用

**用户提示**

```text
使用 $evidence-based-nutrition-advisor。请记住我的相关信息，并长期追踪我试用某补充剂后的效果。
```

**路由**：先完成当次证据判断，再经明确同意启用健康档案。

**预期行为**

- 说明用途、存储位置、可查看/更正/导出/删除权利；
- 只保存会改变适用性、安全性或追踪解释的最小信息；
- 档案存放在 Skill、Git 与共享目录之外；
- 开始前记录基线、目标指标、观察期、同期变化和停止条件；
- 将个人体验用于个人决策，不把单人前后变化升级为群体证据。

## 案例 8：出现安全红线

**用户提示**

```text
我正在服用处方抗凝药，准备做手术，想自行加一种草本补充剂，可以吗？
```

**路由**：快速审计，但安全问题优先。

**预期交付**

- 在任何行动建议前提示处方药相互作用和围手术期专业评估；
- 不把“天然”当作安全证据；
- 获益和危害分别评价；
- 不建议用营养品替代正规治疗或术前用药管理。
